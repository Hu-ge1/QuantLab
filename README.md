# QuantLab · 量化实验室

> 一个 AI 原生的 A 股量化研究 + 实盘工作台（研究框架复刻自 [wei011/quant-watch](https://github.com/wei011/quant-watch)；QMT 实盘能力合并自 **qmt-strategy-studio** 项目；方法论源自华泰金工《自进化Skill：选股策略的自动迭代》与 Karpathy 的 AutoResearch）。
>
> AI 不凭训练记忆「编」数据，而是**调用真实行情接口**做分析；把三套硬核方法论做成了可点的功能：**贝叶斯决策引擎**、**策略自进化引擎**、**AI 策略工坊**；并以内置桥接只读接入 **QMT 实盘**。
>
> **一个应用、一个端口（:8000）。行情来自 akshare 免费接口，无需注册任何账号。**

## 为什么做这个

市面上的「AI 炒股助手」基本都有一个通病：**张口就来**。问它某只票现在多少钱、PE 多少，它从训练记忆里编一个，听起来煞有介事，其实早就过时。

QuantLab 的出发点只有一句话：**让 AI 的每一个数字都有来源，让每一个决策都可追溯。**

- 问行情 → AI 必须先调真实行情接口取数据，不准凭记忆答
- 做决策 → 走贝叶斯概率推理，而不是「我觉得能涨」
- 调策略 → 走约束化的自动迭代，而不是黑箱乱搜参数

## 核心功能

### 1. 🤖 AI 对话（带工具调用 + 长期记忆）

基于 Agentic 工具调用循环，AI 自己决定何时调用哪个工具：

| 工具 | 用途 |
|------|------|
| `ql_search` | 按名称/代码搜索证券（股票/ETF/指数） |
| `ql_get_price` | 历史 K 线与区间摘要 |
| `ql_get_fundamentals` | PE / PB / PS / 市值 |
| `ql_get_index_stocks` | 指数成分股 |
| `ql_screen_stocks` | 全 A 股批量筛选、多因子排序（FFD 优先） |
| `portfolio_get` | 读取用户持仓与盈亏 |
| `bayesian_decision` | 贝叶斯决策分析 |
| `memory_save` | 写入长期记忆 |

护栏设计：最大工具轮数 8、错误预算 3 次、重复调用指纹检测、结果截断——防止 AI 陷入死循环或刷接口。

### 2. 🔎 量化选股 `/screener`

- 扫描范围固定为沪深 A 股主板，支持市值、PE/PB、成交额、换手率和涨跌幅过滤
- 默认使用“中期趋势”风格，并保留均衡、价值两套透明权重；趋势分重点衡量多周期均线排列、均线斜率和价格偏离，避免当天暴涨直接占据榜首
- 纳入 MA60/120/250 多周期趋势结构，可筛选“站上 MA60”，并展示各字段全市场覆盖率
- 支持“严格多头排列”（价格 > MA60 > MA120 > MA250），并标记强趋势、趋势形成、趋势尝试、多头偏热、趋势转弱等阶段
- FFD 全市场日频数据优先，公开批量行情补全估值字段；本地按交易日缓存，缺失字段不补零
- 可选 FFD 历史时点财务补全：对行情预筛前 300 只单批读取毛利率、营收同比和净利润同比；只采用字段级可用于该时点的事实，字段无覆盖时自动移出权重，显式财务过滤则失败关闭
- 候选可一键同步到 QMT 自选，或带着代码、名称和评分进入 AI 深研
- 支持候选组合 120～500 日等权历史体检，对比沪深300并计算收益、波动、回撤与夏普；页面明确提示事后选择偏差，不冒充样本外策略回测

### 3. 🌐 市场复盘 `/market`

每天开盘前 10 秒看完市场全貌（收盘级真实数据，乐咕+新浪免费源）：

- **指数看板**：上证/深成/创业板/沪深300/中证500/科创50，最新收盘 + 当日涨跌 + 5日/20日趋势 + 近 2 月迷你走势图
- **市场宽度**：上涨/下跌家数对比条、涨停/跌停（区分真实涨停）、平盘/停牌、市场活跃度
- **行业板块热度**：49 个新浪行业板块按涨跌幅排序，领涨 TOP8 / 领跌 TOP5，含领涨股与涨幅、板块成交额
- **自动复盘要点**：由当日数据模板化生成（宽度偏强/偏弱、涨跌停对比、中期趋势、最强/最弱板块），无主观臆测

### 3. 🧠 贝叶斯决策引擎 `/decision`

把「要不要买 / 要不要加仓 / 该不该止盈」这种拍脑袋的决定，变成一份**可追溯、可解释、可复现**的概率分析：

```
设定先验 → 证据分级（强/中/弱）→ 贝叶斯更新 → 期望值行动对比 → 敏感性分析
```

- 用**对数几率**逐条更新信念，画出「信念更新轨迹」
- 每个行动算期望值 `EV = P(成立)·上行 + P(不成立)·下行`，推荐 EV 最高的行动
- 敏感性分析：先验扫描 + 逐条剔除证据，告诉你结论**稳不稳、最依赖哪条证据**

> 数学全在 `backend/agent/bayesian.py`，纯 Python、零依赖、完全可复现——不是大模型编的。

### 3. 📈 策略回测 `/strategy`

在浏览器里写聚宽语法的 Python 策略，一键回测，输出净值曲线、夏普、最大回撤、超额收益。服务端策略执行器实现了聚宽 API 子集（`order` / `order_value` / `order_target` / `attribute_history` / `run_daily` / `g` / `set_benchmark` 等）。日频回测只允许读取上一交易日及更早的数据，信号在下一交易日开盘撮合，并模拟资金约束、佣金、印花税、滑点和 A 股 T+1；危险内置函数、导入和内部属性访问会被拒绝。每次回测在一次性 Python 子进程中运行，设有 120 秒硬超时，并记录代码 SHA-256、完整参数、Python 版本和耗时，便于复现与审计。常见策略代码无需删改即可运行。

> 子进程、AST 检查和受限内置函数用于崩溃隔离与降低误操作风险，并不等同于容器或虚拟机级的不可信代码安全沙箱；不要向不受信任的公网用户开放策略执行接口。

### 4. 🧬 策略自进化引擎 `/evolution`

借鉴 Karpathy 的 **AutoResearch** 思想（及华泰金工《自进化 Skill》研报），把选股策略组织成**可执行、可回溯、可约束**的自动迭代循环。三层框架：

- **策略协议层**：策略内核固定，只允许在有界参数空间内调整（每轮只动一个参数，可解释、可归因）
- **版本管理层**：每轮迭代独立成版本，记录配置、指标、父版本、是否保留
- **样本隔离层**：训练集 50% / 验证集 25% / 测试集 25%。验证集决定保留，**测试集只做最终复核，绝不进入调参闭环**

AI 在固定内核下贪心爬山：验证集夏普提升就保留版本，否则回滚；连续多轮无改进则收敛。一次性拉取价格面板缓存到内存，几十次回测在秒级跑完。

> ⚠️ 这套框架最有价值的地方，是它会**诚实地暴露过拟合**：当你看到验证集夏普一路爬升、测试集却纹丝不动甚至下跌时——那不是 bug，那正是「验证集改善 ≠ 真实外推能力」的真相。

### 5. 🧮 网格交易实验室 `/grid`

创建等差或等比网格任务，可自动读取最新基准价和推导上下限，也可手工指定参数。页面支持任务启停、人工价格 tick、网格档位、持仓成本、累计盈亏和成交记录展示。模拟引擎按价格跨越档位触发交易，采用 A 股 100 股整手约束，并限制单格资金与最大持仓金额；状态完整持久化到 SQLite，服务重启后可继续查看。

> 当前网格模块是研究与模拟工具，不会自动向 QMT 提交真实订单。

QuantLab 已**完整合并**原 qmt-strategy-studio 项目（一个应用、一个端口，原 17321 服务可退役）：

### 页面
| 页面 | 能力 |
|---|---|
| `/qmt` QMT 实盘 | 桥接实时看板：资金卡、市场情绪（涨停/跌停/涨跌家数/上证涨幅）、持仓/委托/成交流水、策略信号流、分时图（桥接 tick）、收盘日报、CSV 导出、一键重装桥接 |
| `/studio` 策略工坊 | 描述需求 → AI 流式生成 QMT 策略（大QMT内置/MiniQMT × 回测优先/仅信号/实盘就绪）→ 自动质检（语法 + Python 3.6 兼容，拒绝 `:=`/match）→ 自动修复 → diff 对比 → 一键保存进 QMT 策略目录并注册到「我的策略」（含注册表看门狗自动补注册）；15 个策略模板 + 知识库参考 + 生成历史 |

### 桥接架构

项目里有**两座桥**，名字一样但解决的是完全不同的问题。完整拆解（协议表、风控链、持久化清单、部署与脱敏边界）见 **[docs/bridge.md](docs/bridge.md)**。

| | 启动器桥 | QMT 桥 |
|---|---|---|
| **连接两端** | 双击图标 → Python 服务 | QMT 客户端 → QuantLab 后端 |
| **核心文件** | `QuantLab 量化实验室.bat` · `scripts/start.ps1` · `scripts/stop.ps1` | `backend/qmt_bridge.py` · `backend/routes/bridge.py` · `data/studio/bridge/QMT可视化桥接.py` |
| **关键设计** | 幂等启动、端口预检、依赖自装、日志重定向、按命令行特征精确停止 | 2 秒轮询 push/pull、token 鉴权、指令三态队列、服务端强制风控链、注册表看门狗 |
| **生命周期** | 只在启动/停止那一刻 | 交易时段内持续在线 |

**QMT 桥数据流**（从 studio 原样移植，协议 100% 兼容）：

```
QMT 客户端
  └─ 桥接策略「QMT可视化桥接.py」（每 2 秒推送账户/持仓/委托/成交/行情/情绪）
        ↓ POST /api/bridge/push   GET /api/bridge/pull   （X-Bridge-Token 鉴权）
QuantLab 后端 qmt_bridge.py（内置桥接状态机）
  ├─ 进程内直读 → /qmt 看板、AI 对话 qmt_account 工具、持仓页实时账户
  ├─ 指令队列 + 软风控：allow_order 总开关（默认关）/ 交易时段拦截 / 白名单 / 单笔上限 / 每日次数
  └─ 持久化：bridge_state / signals / daily_reports / ticks_history（30s 落盘）
```

- **迁移**：首次启动自动导入旧 studio 的 config（含 bridge_token，存量桥接策略仍可鉴权）、模板库、知识库、历史
- **切换**：在 `/qmt` 页点「重装桥接到 QMT」——桥接脚本会被改写为推送 QuantLab（:8000），旧版自动备份；然后在 QMT 里停止旧桥接、重新运行新桥接
- 只读通道不变：持仓管理页实时账户、「刷新价格」走 xtdata tick
- **为什么要在 QMT 里放一个「哨兵」策略**：QMT 的量化能力以进程内策略模型的形式存在、没有对外 HTTP 接口，所以桥采用「QMT 主动外推」而非「服务端主动连入」——不开监听端口、不动防火墙、QMT 崩了也不影响服务端。代价是指令延迟下限为 2 秒，不适合日内高频。

### 关于交易（L1/L2/L3 分级，涉及真实资金）

| 级别 | 能力 | 状态 |
|---|---|---|
| L1 手动下单 | `/qmt` → 交易 Tab：代码/买卖/限价市价/股数 → 弹窗二次确认 → 桥接执行 | ✅ 可用 |
| L2 信号半自动 | 策略信号 → 设定股数 → 点「执行」转真实订单 | ✅ 可用 |
| L3 全自动 | 策略信号命中规则表 → **自动**下单（规则：策略/代码/方向/股数，`*` 通配） | ✅ 已建，**默认关闭** |

**服务端强制风控链**（前端绕不过，每条指令依次过）：总闸 kill-switch → 允许下单开关 → 代码格式 → 整手校验 → **交易时段拦截** → 白名单 → 单笔股数上限 → 每日笔数上限。全程审计留痕（`/qmt` 交易 Tab 底部实时可查）。

**三重保险**：① 交易总闸（红色紧急停机按钮，一键拦截一切下单）；② 当日亏损熔断（资产回撤 ≥ 阈值自动停用全自动，阈值可调，0 为关闭）；③ QMT 端物理保险（桥接策略停止 = 一切执行终止）。

> ⚠️ **风险声明**：自动交易可能导致资金快速损失。历史上手请用最小股数 + 白名单 + 低频次规则试跑，确认链路行为符合预期后再逐步放开。模型如有 bug，风控链只能限损不能保盈。所有交易决策与后果由用户自行承担。

## 快速开始

### 一键启动（推荐）

| 平台 | 启动 | 停止 |
|---|---|---|
| Windows | 双击 `启动 QuantLab.cmd` | 双击 `停止 QuantLab.cmd` |
| Windows（已挪到桌面） | 双击 `QuantLab 量化实验室.bat` | 用上面的停止 `cmd` |
| Git Bash / macOS / Linux | `./start.sh` | `./stop.sh` |

启动器会自动完成这一串：Python 预检 → 端口占用检查 → 依赖自动安装 → 后台拉起服务 → 健康探测 → 打开浏览器。日志写在 `logs/`，重复双击不会启动第二个实例。

> `start.sh` 取 PATH 上的第一个 `python3` / `python`。如果机器上有多个 Python（conda、便携版、系统版混用），用 `QUANTLAB_PYTHON=/path/to/python ./start.sh` 指定，免得依赖装进错的环境。

### 手动启动（开发）

```bash
# 后端（Python 3.10+）
cd backend
pip install -r requirements.txt
python main.py            # http://localhost:8000

# 前端（开发模式，可选）
cd frontend
npm install
npm run dev               # http://localhost:5173（代理 /api → 8000）
```

前端已构建时（`frontend/dist` 存在），直接打开 **http://localhost:8000** 即可使用（单端口模式）；页面按路由懒加载，首次只下载当前功能所需代码。开发改动后 `cd frontend && npm run build` 重新构建。

后端默认只监听 `127.0.0.1`，并校验本机 Host 与浏览器 Origin，避免恶意网页跨站调用策略执行或交易 API。如需局域网/公网部署，请在受控反向代理后增加正式身份认证与 HTTPS，不要直接放开监听地址。

### QMT 路径配置（只有要用实盘接入时才需要）

QMT 的安装目录**不写死在代码里**，以免把券商名和个人目录结构带进仓库。解析优先级：设置里的值 → 环境变量 → 空（未配置）。未配置时「重装桥接」会直接提示目录未配置，**不会**把策略文件误写进别的地方。

| 环境变量 | 含义 | 示例 |
|---|---|---|
| `QUANTLAB_QMT_PYTHON_DIR` | QMT 策略目录（桥接策略存放位置） | `D:\QMT\python` |
| `QUANTLAB_QMT_INSTALL_DIR` | QMT 安装根目录（MiniQMT 只读通道用） | `D:\QMT` |
| `QUANTLAB_LEGACY_STUDIO_DIR` | 旧 qmt-strategy-studio 目录，仅用于一次性配置迁移；不设则跳过 | — |

### 首次使用设置

打开页面进入「设置」：
- **AI 大模型**：选提供商 → 填 Base URL + API Key + 模型名（推荐 DeepSeek，便宜好用）。不填也能用——策略回测/自进化/贝叶斯决策/持仓管理都不依赖 AI
- **数据源**：点「测试数据源」确认 akshare 连通（失败自动 demo 模式）

> 所有密钥只存在你本地的 SQLite（`backend/data/quant_lab.db`），不上传任何服务器。

## 与原版（quant-watch）的主要差异

| | quant-watch 原版 | QuantLab 复刻版 |
|---|---|---|
| 行情数据 | 聚宽 jqdatasdk（需注册账号，免费账号有数据时间窗） | akshare 免费（无账号；东财+新浪双通道）+ demo 兜底 |
| 时间窗探测 | `_get_allowed_end()` 探测机制 | 不需要（免费接口无窗口限制） |
| 回测取数 | 逐日逐票拉取 | 按证券整段预取 + 内存缓存（更快） |
| SPA 托管 | 静态目录直挂 | 404 回退 index.html（深链接可直达） |
| AI 工具命名 | `jq_*` | `ql_*` |
